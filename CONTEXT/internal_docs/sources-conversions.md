# Source Conversion Tracking

Per-project tracking for the conversion to the submodule + `museum-ready/original` workflow described in [sources.md](sources.md). Each section below is **agent-actionable** — an agent should be able to read one project's section and execute the conversion independently.

## Status legend

Each row has six status columns; a project is "fully audited" when every applicable column is ✅ (or ➖ when not applicable).

### State values

Most columns use the same five states. Read them as a progression:

- `🔴 not-started` — nothing exists for this dimension
- `🟠 stubbed` — placeholder exists so visitors see _something_ (e.g. the museum entry renders `<Placeholder label="Coming soon" />`, or schema fields exist with default values but aren't filled in for this project). Honest acknowledgement without committed work.
- `🟡 in-progress` — partially done; see project notes
- `🟢 done` / `✅ done`
- `➖ n/a` — dimension doesn't apply (backend-only with no submodule, no source repo to meta-sync, etc.)

Per-column meaning:

| Column     | What it tracks                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Routes** | Every museum URL this project (or pair) serves, each with its own status dot. The dot is the per-URL version of the ✓ column: green when a human has loaded that specific URL and confirmed it works. For paired projects (any project with `siblingApiClient` / `siblingFrontend`), this column lists BOTH the frontend route and the `/api-client?api=<slug>` viewer route, even though they have separate rows for their respective Schema work — so you can see "is the api half of admin-portal verified" without leaving the admin-portal row. The `-api` row owns its own Schema entry but its Routes column mirrors the same pair, so both rows agree at a glance. **For multi-page originals, list the canonical first-page URL (`/<path>?page=<first>`) — that's what `projectLandingUrl` resolves the bare URL to, and what every in-app link points at; bookmarking the bare URL just redirects there anyway.** |
| **Conv**   | Submodule exists, `museum-ready/original` is the source of truth, `sources.generated.json` populated, sync.config recipe in place.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **GH**     | `pnpm sync:source-meta <slug>` has been run: legacy default branch renamed to `original`, `museum-ready/original` is the GitHub default, repo description prefixed and rewritten from `Project.synopsis`, homepage set, topics added, banner committed to museum-ready README.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Fix**    | Hosting fixes on `museum-ready/original` so the museum copy renders correctly: dead URL substitutions, geolocation timeouts, API key redactions, asset path rewrites, etc. `➖ none-needed` is common — originals that ran cleanly as-is. Iframe-fit fixes (see Frame column) live here too when they require source patches.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Frame**  | Iframe-fit audit. The museum's `OriginalFrame` auto-sizes the iframe to its content height (so the museum's outer leafBody is the single scroll surface — no internal iframe scrollbar fighting with the museum's custom one). Some source CSS patterns misbehave inside this contract: `position: fixed` floats over content as the leafBody scrolls; `position: sticky` glues to the top forever because the iframe IS its full content height; `background-attachment: fixed` locks to a viewport that's now arbitrarily tall; `min-height: 100vh` on body+flex containers can produce weird inflation. `✅ clean` = works as-is. `🟡 partial` = renders but has visual weirdness worth flagging. `🔴 broken` = source needs a museum-ready fix (note specifics under the row's Notes; the fix lives on `museum-ready/original` and gets logged in the Fix column too). `➖ n/a` = backend-only or no iframe.            |
| **Schema** | `projects.tsx` entry carries the right shape: `repo`/`synopsis`/`notes`/`techOriginal`, `pages` if multi-page, `siblingApiClient`/`siblingFrontend` if half of an api+client pair, `plannedTiers` if narrower than all three. `🟠 stubbed` means the entry exists with minimal fields but the project hasn't been fleshed out.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Prose**  | Per-tier copy completeness. Each tier in `plannedTiers` gets its own status dot. Green when ALL of the following are set for that tier: (a) one-line `description` (the sidebar/rail teaser — projects.tsx has `description`, api-data.ts has it on each entry); (b) long-form `notes` text (projects.tsx `notes.<tier>`, api-data.ts `notes` field on the entry); (c) cross-link to the partner where applicable (`siblingFrontend`/`siblingApiClient` in projects.tsx, `relatedRoute` in api-data.ts). For backend-only rows (`-api` slugs and standalone backends like jaskis, music-tour-api), the source of truth is `src/app/(museum)/api-client/api-data.ts` (an entry exists per-tier in `APIS_ORIGINAL` / `APIS_ENHANCED`). For everything else, the source is `projects.tsx`. `🟠 stubbed` means a field exists but the text reads as placeholder. `➖` means the tier isn't in `plannedTiers`.                   |
| **✓**      | Roll-up of the Routes column. Green when every route in this row's Routes list is green. The Routes column is the source of truth for per-URL verification; this column is the at-a-glance answer to "is this project entirely audited."                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

A project is "fully audited" when every applicable column is `🟢`/`✅` (or `➖`).

## Lessons learned (append as conversions happen)

### Server Action mutations need their own guard helper (2026-05-24)

When a museum entry's mutations go through React Server Actions rather than `/api/*` routes (rest-rant-ssr is the first such surface), the api-guard + museum-toast SW pattern does not apply: Server Action POSTs don't carry a URL prefix, the SW can't intercept them by path, and `guardMutation(request)` doesn't have a `Request` to read headers from. The fix is `guardServerAction()` (sibling helper in `src/lib/api-guard.ts`) which reads headers via `next/headers`, runs the same session-lookup + rate-limit + actor shape, and returns a tagged-union result the caller can branch on to redirect-with-error. Tier classification is the caller's responsibility (passed into `writeAuditEntry` directly) because Server Actions don't have a URL prefix to derive tier from. Any future project that exposes Server Action mutations on a museum-gated surface should reach for `guardServerAction()` rather than reinventing the auth check.

### Static originals: the served CSS may be Prettier output, and `.DS_Store` needs an allowlist (2026-10-24)

Three things came up while converting the html-css static leaves (restaurant-menu first), and they apply to every static original committed before `public/originals/` entered `.prettierignore`:

- **The served CSS may not be the submitted CSS.** Museum commit 215b7c3 (2026-05-05) ran lint-staged's `prettier --write` over every `.css` it added under `public/originals/`, so those served stylesheets are Prettier output (re-indented, quotes normalized, `.1s` → `0.1s`, semicolons added), not the submitted bytes. A sync from `museum-ready/original` puts the submitted bytes back, which shows up as a whitespace-heavy diff on each `.css`. That diff is expected. Check it rather than assume it: `node_modules/.bin/prettier --no-config --stdin-filepath x.css < <synced file>` must reproduce `git show HEAD:<served file>` byte for byte. Anything left over after that is a real difference and needs its own explanation.
- **Source repos that track `.DS_Store`.** Several UNLV-era repos commit `.DS_Store` and `assets/.DS_Store`. The museum `.gitignore` drops `.DS_Store`, so copying it in would leave the local lockHash out of step with a fresh clone's. Give the recipe an `include` allowlist that names the subdirectories (`assets/css`, `assets/images`, …) instead of `assets`.
- **Compare like with like in the browser.** A real mouse click leaves the pointer over the newly loaded page, so its computed styles pick up `:hover` and won't match a page that was opened another way. When comparing local and production computed styles, open the pages the same way on both sides (for example, `a.click()` from a script on both).

### JS static originals: held keys, background tabs, autocrlf sizes, backend-only drift (2026-10-24)

Four things came up while converting the js-static group (milestown, stock-charts, copycat, jacks-paint, web-game):

- **Games that poll held keys need a real hold.** milestown and web-game move on a 1 ms interval while a key is down. A tool keypress releases the key about 1 ms later, before any tick runs, so the character never moves and the game looks broken when it isn't. Hold the key instead: dispatch `keydown` on the iframe document, wait a few hundred ms, then dispatch `keyup` (the handlers read `e.key`), and run the same sequence on production.
- **Compare in a foreground tab.** Chart.js handles canvas events through `requestAnimationFrame`, which a background tab pauses, so legend clicks and tooltips silently do nothing there. Bring the page to the front before an interaction walk, on both sides.
- **"Modified" with an empty diff.** With `core.autocrlf=true`, a synced CRLF copy of a file whose index entry was recorded from an LF working file shows as `M` in `git status` while `git diff` is empty: git sees the size change and reports it without comparing content. `git hash-object --path=<served path> <file>` confirms the blob is unchanged, and staging the directory clears it. Source repos that commit CRLF blobs (jacks-paint) also come out as the museum's existing LF blobs through the same clean filter.
- **A backend-only submodule's own commits break every commit.** Backend-only recipes (jaskis, music-tour-api, rest-rant-ssr) hash the whole submodule working tree. When a new commit is checked out in one of them (for example a pnpm-normalize backfill), `verify:locks` fails for every museum commit, whatever is staged, until that slug is re-synced. Re-sync it in the same change that bumps its pointer.
